# UniMeet proposal & delivery workflow

This private repository contains the UniMeet proposal and an illustrative development workflow prepared by Giuseppe Castro.

> **Demonstration only.** The sample issues, commits, pull request and milestones demonstrate how progress can be reviewed. They do not represent completed MVP development, client approval, validated matching quality, or an agreed delivery schedule.

## How to follow progress

1. Open the delivery overview issue for the milestone map and links to sub-issues.
2. Open each sub-issue for its scope, acceptance criteria and latest developer update.
3. Follow the linked pull request to see a specific proposed change, its verification and merge record.
4. A closed demonstration issue means that its **sample documentation deliverable** is complete, not that a production feature has shipped.

No students, universities or client reviewers are invited or assigned in this example. Demonstration comments are written from the developer's perspective; they are not client feedback or approval.

## Proposed milestones

| Milestone | Review outcome |
| --- | --- |
| 1 · Scope & design | Agreed MVP boundary, screen flow, data fields and acceptance criteria |
| 2 · Matching & interfaces | Working student/university journeys and a measurable matching baseline |
| 3 · Validation & launch | End-to-end checks, operational handover and launch readiness |

Dates, commercials and scope remain subject to the written proposal and alignment with Davide. Issue labels distinguish the sample workflow from actual delivery.
